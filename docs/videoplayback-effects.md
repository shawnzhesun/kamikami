## Composition recipes and limits

- **Opening montage:** use Color remap on a background drawing or inset image; Chromatic fringe for accents; Broken TV signal in Wave mode on the inset; Angled picture plane and Camera zoom for its movement. The opening folded shape is more complex than this wave approximation.
- **Block-glitch cuts:** place Broken TV signal on the short incoming element, select Digital blocks, and choose At clip start timing. Set the other passes' timing or strength individually. This does not automatically move the clip or synchronize it to music.
- **Spin/zoom cut:** apply Motion smear to the incoming clip for roughly 0.3–0.5 seconds. Choose Spin and set an angle, or choose Zoom. Add Orbiting composition or Camera zoom if the artwork should also move. Smears sample one frame at 12 transformed positions, so very wide smears can show discrete trails.
- **Mirror/tile shot:** put Image repetition on the background only, then keep the character and lyrics above it. For kaleidoscope, use artwork with detail near the sampled wedge. It folds one source wedge; it cannot create the different hands and characters seen in the video. Fine edges can alias or soften because these layouts resample the source through displacement maps.
- **Interface graphic:** Graphic rings plus bloom on a background plate, with separate text, rectangles and arrows. This recreates the circular treatment, not the original interface design.
- **Fireworks scene:** select Radial bursts in Particles on the background; adjust color, secondary color, count, speed and seed. Add Soft highlight bloom if needed. Keep figures above the background to preserve their silhouettes.

Drawn characters, scarves, signs, doors, clocks, handwritten marks, comic panels, text grids containing different glyphs, and photo/background changes are layer content or editing. Clock-hand motion can be built with rotation channels on separate hand artwork; a clock face is not a generic filter. Selective clothing colors require separately isolated artwork or masks. A possible wide-angle/fisheye background around 01:39 is baked into the source image and cannot be identified confidently as a post effect from these samples.

## Rendering, compatibility and validation

The new modes use the same declarative graphics pipeline in the library preview, timeline and export. Transform sampling reads SVG SourceGraphic rather than creating extra video/audio players. Noise, block patterns and particles derive from clip time and seed. Split and trim offsets preserve their phase.

New kinds and mode fields export with the **kamikami-visual-v3** effect engine. Existing v1/v2 bundles continue to import. Older engines are explicitly rejected for new modes so an older reader cannot silently discard their settings. Project JSON still uses version 1 and should be opened in this version or newer.

Automated tests cover uniqueness, mode validation, parameter round trips, engine compatibility, tile coordinates, mirror/kaleidoscope symmetry, bounded sampling maps, deterministic output, split continuity, and a single video source per effect stack.

Filter samples were reviewed with the local SVG renderer on original geometric test artwork. Its nested-SVG feImage handling required rasterizing the procedural input maps before that check; this validates the filter geometry and compositing, not browser resource loading. Chromium launch remains blocked in the development environment, so in-app playback, performance and actual Remotion video export still require verification. Large smears and dense repetitions are more expensive than the simple color/overlay passes.
